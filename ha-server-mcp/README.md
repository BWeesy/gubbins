# ha-server-mcp

A small [MCP](https://modelcontextprotocol.io) server that gives an AI
assistant narrow, auditable access to a NixOS home server: check the host's
health, read glowbridge's status and an allow-list of service logs, and
trigger a NixOS upgrade or rollback from the host's git-held config. Nothing
else.

It speaks MCP over stdio and has no network listener. sshd launches it as the
forced `command=` of one restricted SSH key, so SSH is the authentication and
the client cannot choose what runs.

## Tools

| Tool | Effect |
|---|---|
| `host_health` | Uptime, load, memory, disk usage, failed systemd units, the Home Assistant VM's libvirt state, the current/previous NixOS generation and whether a reboot is pending. Read-only. |
| `glowbridge_status` | glowbridge's systemd state plus its `status.json`. Read-only. Never reads `state.json`. |
| `service_logs(unit, lines)` | Journal tail for one allow-listed unit, capped at `maxLogLines`. Read-only. |
| `system_upgrade` | Starts the fixed upgrade unit (`nixos-rebuild switch --refresh --flake <upgrade.flake>`) and returns at once. |
| `upgrade_status(log_lines)` | State, result and log tail of the last upgrade and rollback runs, plus generations. Read-only. |
| `system_rollback` | Starts the fixed rollback unit: back one generation, then activate. Returns at once. |

There is no tool that runs an arbitrary command, and none ever will be added.

## Design decisions

**Nothing the caller sends reaches a privileged process.** Every privileged
action is a fixed shell helper generated by the NixOS module, with all paths
and names baked in. sudo allows each helper by exact store path followed by
`""`, which in sudoers means "no arguments". The only caller inputs are a
unit name (looked up in the allow-list; it only *selects* a helper) and line
counts (applied in the server, after the helper has run).

**An upgrade only ever builds one flake ref.** The ref lives in the host's
own config. Running `nixos-rebuild` is effectively root, so being able to
choose *what* it builds would be root; being able to say *when* is not. What
the box runs therefore changes only by merging to that config repo. Fetch
it with a read-only deploy key (`upgrade.sshKeyFile`), so a compromised host
cannot write itself back into its own config and survive the next rebuild.

**A restricted, forced-command key.** The authorized_keys line is
`from="<allowFrom>",restrict,command="ha-server-mcp --config …" <key>`.
`restrict` turns off ptys, port/agent/X11 forwarding and `~/.ssh/rc`; the
forced command makes any requested command irrelevant; `from=` pins the key
to known client addresses. The `claude` user is a system user outside
`wheel` with no usable password.

**glowbridge's token stays put.** glowbridge's state directory is `0700`
under DynamicUser, so status is read by a root helper that opens exactly
`status.json` with `iflag=nofollow`: a compromised glowbridge cannot swap in
a symlink to `state.json` or `/etc/shadow`.

**Rollback needs no network.** It steps the system profile back one
generation and activates it, so it still works when the upgrade source is
what broke. It is relative: running it twice goes back two generations. The
next `system_upgrade` returns to the config repo's branch.

**Degrade, don't fail.** Each section of `host_health` is probed on its own;
no virsh, a sudo refusal or an unreadable mount shows up as an `error` in
that section only.

## Setup (NixOS)

From a flake host config:

```nix
{
  inputs.gubbins.url = "github:BWeesy/gubbins";

  outputs = { nixpkgs, gubbins, ... }: {
    nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./configuration.nix
        gubbins.nixosModules.ha-server-mcp
        {
          services.ha-server-mcp = {
            enable = true;
            ssh.publicKey = "ssh-ed25519 AAAA... claude@desktop";
            ssh.allowFrom = [ "192.168.1.20" "100.64.0.7" ];
            upgrade.flake = "git+ssh://git@github.com/you/host-config?ref=main#myhost";
            upgrade.sshKeyFile = "/root/.ssh/host-config-deploy";
            vm.name = "haos";
            extraLogUnits = [ "libvirtd.service" ];
            diskPaths = [ "/" "/nix" ];
          };
        }
      ];
    };
  };
}
```

Things the module cannot do for you:

- **Known hosts.** The upgrade fetches with `StrictHostKeyChecking=yes`, so
  the git server's host key must be in `programs.ssh.knownHosts`.
- **sshd allow-lists.** If the host sets `services.openssh.settings.AllowUsers`
  or `AllowGroups`, add the `claude` user.
- **sudo.** The rules are for classic sudo (`security.sudo`); the module
  asserts it is enabled and that `execWheelOnly` is off.
- **Updating inputs.** The upgrade builds the flake *as locked*. To pick up
  a newer gubbins (say, a glowbridge release), bump the host config's
  `flake.lock` in a reviewed change; the upgrade never updates it.

Module options are documented inline in [`nix/module.nix`](nix/module.nix).

## Client

Point an MCP client at `ssh` with a dedicated key, for example in Claude
Code's config:

```json
{
  "mcpServers": {
    "ha-server": {
      "command": "ssh",
      "args": ["-i", "~/.ssh/id_ed25519_claude_haserver", "-o", "IdentitiesOnly=yes",
               "-o", "BatchMode=yes", "claude@ha-server"]
    }
  }
}
```

## Development

```
uv run --script test_ha_server_mcp.py         # unit tests (fakes only)
uvx ruff@0.15.22 check *.py nix/*.py
nix build .#checks.x86_64-linux.ha-server-mcp-vm   # boots the module in a VM
```

The unit tests drive the tools through a fake runner and filesystem and never
touch a real host. [`nix/vm-test.nix`](nix/vm-test.nix) covers the real
wiring: it sshes in as `claude`, calls every tool over MCP, and checks that
sudo grants only the helpers, that a helper refuses extra arguments, and that
a symlinked `status.json` is refused. CI runs both.

Dependencies are pinned per script in `*.py.lock`; after changing a script's
PEP 723 block, re-lock with `uv lock --script <file>`. The `mcp` SDK is held
below 2 because nixpkgs ships the 1.x line and the Nix package uses it.
